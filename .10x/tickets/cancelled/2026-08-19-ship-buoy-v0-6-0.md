# Ship Buoy v0.6.0 and Establish Reusable Releases

## Disposition

The reusable annotated-tag publisher was reviewed, integrated, and enabled,
but the first tagged invocation stopped in its read-only test stage. Buoy
v0.6.0 was not published. On 2026-08-20 the owner selected v0.6.1 instead of a
recovery publisher, so this ticket is cancelled in favor of the bounded
v0.6.1 release ticket.

The public annotated `v0.6.0` tag is permanent audit history. Tag object
`1ffb70f5656f48c782defbe252dab44426134343` peels to exact main commit
`701d73ebbf6a8c3b2c664a0295374dcb4283283c` and has message `Buoy v0.6.0`.
It must never be deleted, recreated, overwritten, or moved, and no GitHub
Release may be constructed for it under this or the successor ticket.

## Completed scope

- Release preparation and the reusable least-privilege publisher reached
  `develop` through task PR #137 and exact main through release PR #138.
- Exact-main CI passed at release merge
  `701d73ebbf6a8c3b2c664a0295374dcb4283283c`.
- Repository immutable Releases were enabled and remain enabled.
- The exact annotated v0.6.0 tag was created and pushed once at that main
  commit, starting Release workflow run `32329737394`.

## Stopped publication

Both `Python 3.11` and `Python 3.13` jobs in run `32329737394` failed only in
`DynamicVersionTests.test_clean_editable_install_derives_development_version_from_vcs`.
The fixture asserted that an editable checkout always derives a development
version; the exact tagged checkout correctly derived stable `0.6.0` for both
package metadata and the module. This was a hermetic test-fixture defect, not
an application, package, tag, or release-workflow state-machine failure.

Because the matrix failed, `Build distributions` and
`Publish immutable GitHub release` were skipped. The run retained zero
artifacts and created no GitHub Release, draft, release asset, or attestation.

## Successor scope

`.10x/tickets/2026-08-20-ship-buoy-v0-6-1.md` owns the public v0.6.1 release
surfaces, the hermetic VCS-version fixture correction, ordinary integration,
main promotion, and a normal annotated-tag invocation of the already reviewed
publisher. It does not own a recovery workflow or manual dispatch path.

No application behavior, dependency, lockfile, package-version authority,
PyPI publication, provider/model/data operation, real Buoy-home access,
branch-protection change, tag movement, or unrelated hosted mutation is
authorized by either this disposition or its audit evidence.
