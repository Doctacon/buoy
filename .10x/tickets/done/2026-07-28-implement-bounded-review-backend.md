# Implement Bounded Review Backend

## Scope

Implement the service/API portions of `.10x/specs/command-center-bounded-inventory-transport.md` and `.10x/specs/command-center-coalesced-plan-review.md`: server-side plan/namespace filters, bounded namespace plan history, typed combined review, and synchronous combined endpoint.

## Acceptance criteria

- Plans and Namespaces filters validate and apply to the cached snapshot before pagination with filtered totals and deterministic ordering.
- At least 1,000-plan structural tests cover filtering, totals, pagination, invalid filters, and unchanged cache rebuild behavior.
- Namespace detail defaults to 20 plans, max 100, reports total/offset/limit/truncation accurately, and never returns unbounded plans.
- Combined service resolves/binds once, invokes the existing complete verifier exactly once with both windows, reconstructs all three sections, checks post identities once, and introduces no verification cache.
- Synchronous `/api/v1/plans/{plan_id}/review` and additive query parameters/routes use structured errors and current bounds.
- Standalone detail/chunks/stale each still invoke complete verification once; tamper/replacement/ABA/corruption regressions and provider/model/source inertness pass.

## Evidence expectations

Focused service/API/plan-artifact tests and verifier instrumentation with exact call counts. Progress is append-only.

## Explicit exclusions

Frontend behavior, artifact/state schemas, summary-cache changes, verifier bypass/cache/token, mutation authority, provider calls, graph work, and unrelated refactors.
